CI PIPELINE — Option B (single approval gate)
==============================================

  Developer pushes branch, opens PR
         |
         v
  +--------------------------------------------------------+
  |  validate-pr.yml                                       |
  |                                                        |
  |  [dev] [prod]  (matrix)                               |
  |    dbt compile --target <env>                          |
  |    deploy_semantic_views.py --dry-run                  |
  |    deploy_agents.py         --dry-run                  |
  |    detect_sv_drift.py       (advisory)                 |
  |    validate_spec_format     agents/specs/*.yml         |
  |    pytest tests/ (unit only)                           |
  +--------------------------------------------------------+
         |
         |  CI passes; PR approved; merged to main
         v
  +--------------------------------------------------------+
  |  deploy-prod-validated.yml   (auto on main push)       |
  |                                                        |
  |  1. snapshot_state  --env prod                         |
  |  2. deploy_semantic_views (dbt run, SV DDL)            |
  |  3. deploy_agents   --env prod                         |
  |        -> ADD LIVE FROM LAST                           |
  |        -> MODIFY LIVE SET SPEC                         |
  |        -> COMMIT LIVE (creates VERSION$N)              |
  |        -> MODIFY VERSION LAST SET ALIAS = validated    |
  |  4. smoke_test      --env prod --alias validated       |
  |  5. run_ci_eval     --env prod --alias validated       |
  |                                                        |
  |  On eval PASS: upload artifact {version:VERSION$N}     |
  |  On eval FAIL: fail; `production` alias unchanged      |
  +--------------------------------------------------------+
         |
         |  *** ONE HUMAN APPROVAL GATE ***
         |  manual dispatch: promote-validated-to-production.yml
         |  GitHub env: production-promote (required reviewers)
         v
  +--------------------------------------------------------+
  |  promote-validated-to-production.yml                   |
  |                                                        |
  |  1. read version currently under alias=validated       |
  |  2. ALTER AGENT <fqn>                                  |
  |       MODIFY VERSION <that version>                    |
  |       SET ALIAS = production;                          |
  |  3. smoke_test      --env prod --alias production      |
  |  4. run_ci_eval     --env prod --alias production      |
  +--------------------------------------------------------+
         |
         |  incident: someone triggers rollback.yml
         v
  +--------------------------------------------------------+
  |  rollback.yml   (env: production-promote if env=prod)  |
  |                                                        |
  |  1. rollback.py --env prod --agent <name>              |
  |       --alias production [--to VERSION$N]              |
  |  2. ALTER AGENT <fqn>                                  |
  |       MODIFY VERSION <target> SET ALIAS = production;  |
  |  3. smoke_test --env prod --alias production           |
  +--------------------------------------------------------+


DEV loop (parallel, no gate)
----------------------------
  Developer pushes feature branch
      -> deploy-dev.yml runs automatically
      -> dev env iterates freely; alias=latest moves on every deploy
